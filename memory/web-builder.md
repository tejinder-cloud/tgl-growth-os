**Department:** marketing
**Created:** 2026-10-23

## Accumulated Heuristics & Rules
- Service Configuration Pattern: Railway root-directory builds get an isolated context; never copy shared config into a service — fetch it. Services reading shared repository configuration (e.g. `config/agents.yaml`, `config/doors/*.yaml`) must fetch from the repository's `main` branch via the GitHub Contents API using `GITHUB_TOKEN`, cached in-memory (5 minutes), with a local-file fallback for local development only.
- Proposal execution protocol: A proposal is not executed until the Architect answers. Where a change is judged to be a craft decision within discipline under AGENTS.md mandate 6, state so explicitly ("craft decision — executed and recorded") instead of "Decision: Executed Option A". Where a proposal expands scope, mark it "awaiting approval" and build the rest within approved scope. Never self-approve.
- Desktop header is sticky (`position: sticky; top: 16px`); on mobile (<768px), header uncouples to `position: relative; top: auto;` to preserve viewport space for the bottom sticky pill.
- Sticky mobile CTA pill (`.tgl-sticky-pill`) appears at scroll > 1200px and hides via IntersectionObserver when `cta-band` or `footer` is in view.
- Never edit `tgl-theme/theme.json` manually; edit `design-system/tokens.json` and run `site/build-theme-json.js`.
- Always set `font-display: optional` on Fraunces to eliminate webfont swap delay and layout recalculation.
- Never preload body font (DM Sans); preload only display hero faces (`fraunces-latin-normal.woff2` and italic) with `fetchpriority="high"`.
- Test hygiene standing rule: tests never write to `decisions/` or `logs/` on main — not even to delete afterwards. Write to `logs/.test/` and clean it, or mock the write. Any issue, PR, card or log line created by a test is labelled `type:test`, posts only to `#ops`, and is closed by the test itself. Never post test executions to real channels (`#standup`, `#marketing`, `#site-build`, `#approvals`, `#architect`) or leave unclosed test artifacts.
- Honesty standing rule: Every success message a user sees MUST derive strictly from the verified API response of the action it describes. "simulated", synthetic timestamps, or any placeholder values can NEVER reach a user or live Slack channel under any circumstance. Never report a write, broadcast, card dispatch, or state update that didn't happen or failed. If an API call fails or returns an error, fail loudly, log the exact error, and report the failure truthfully to the user.
- Git branch and PR standing rule: Always branch from fresh `main` (`git fetch && git checkout -b <branch> origin/main`) and rebase onto `origin/main` before opening a PR to prevent merge conflicts with recently merged changes.
- PR Description standing rule: PR descriptions must never use closing keywords (fixes, closes, resolves) for an issue the PR does not complete. Referencing an issue for context or reset must use non-closing phrasing (e.g. "relates to #N", "resets runner state for #N") so GitHub does not auto-close issues and automated catch-up queries do not mistake referenced issues for completed work.

## Pitfalls & Anti-Patterns Avoided
- 2026-10-24 Honesty & False Reporting Breaches:
  1. Gate 0 breach (13:31 IST): Slack card reported "Recorded in decisions/2026-10-24.md" before checking the GitHub Contents API response (which failed due to a branch ruleset rejection). Remedied by strictly verifying 200/201 response status before posting "Recorded"; on any other status, post "Decision captured in Slack but NOT written to the repo — <status> <message>" in-thread and to #alerts. Never report a write that didn't happen.
  2. /standup breach (18:52 IST): /standup command in #standup replied "broadcast complete (ts: simulated)". Leaked because: (a) options.targetChannel was evaluated as truthy in isTest, causing the production container to switch into test mode; (b) Anthropic synthesis hit max_tokens (1000 out) resulting in no_text error on chat.postMessage; (c) the failure was swallowed and a synthetic timestamp "simulated" was sent in the user ephemeral reply. Remedied by: (a) locking test mode strictly to process.env.TGL_TEST_MODE === "1", refusing to boot if RAILWAY_ENVIRONMENT is set; (b) ensuring every chat.postMessage carries non-empty fallback text plus blocks; (c) raising max_tokens to 2000 and tightening prompt to ~400 tokens; (d) throwing on any Slack post failure so false success strings can never be formed; and (e) including real message ts and cost line in the response.
- 2026-10-24 Test write breach: Test suite wrote test decision and architect log directly to `decisions/2026-10-24.md` ("Approved revised CTA copy for mobile") and `logs/2026-10-24/architect.md` on main. Remedied by deleting `logs/2026-10-24/architect.md` and reverting the test decision line via the GitHub Contents API. Standing rule enforced: tests must never touch production `logs/` or `decisions/` on main under any circumstance (not even for cleanup); use `logs/.test/` with immediate cleanup or mock the write.
- Never duplicate repository-level `config/` into subservices; having two copies of configuration breaks the single-source rule in `ORG.md §3`.
- Never self-approve proposals or execute unapproved scope expansions before Architect review.
- Never add inline script or style tags; tracking events must use `data-tgl-event` attributes.
- Slack Event Subscriptions verification observation & mounting diff:
  - Both `/slack/commands` and `/slack/events` share identical `express.raw({ type: "*/*", limit: "5mb" })` capture.
  - Middleware order: Synchronous `url_verification` sits as the first middleware on `/slack/events`, returning `200 { challenge }` in <1ms without awaits or external dependencies. Content-type parsing follows, followed by `/slack` entry logging and HMAC verification.
  - Redirects & status: Neither endpoint issues redirects (no 301/302/307) or 404 on POST; both return HTTP 200 on synthetic IPv4 POSTs.
  - Network & routing: `tgl-growth-os-production.up.railway.app` publishes no `AAAA` DNS record (IPv4 `A` at `69.46.46.67`). The endpoint is responsive over IPv4 (~0.5s). Slack's verification request was captured at `webhook.site` (with valid headers and matching signature) but was not observed arriving at the Railway application when targeting the Railway domain; cause: unknown — under investigation.
  - Operational rule: Zero application-level differences exist in code; `/task` is the operational trigger until Slack events verify.
