## Spec check 1: hero form to the /aeo endpoint
The spec says to report and stop if the endpoint cannot accept the two-field version. From the code it can: `home_hero` is the only source with the lighter validation, and every other source still needs the full /aeo field set. No fields were added to the hero.
Still needed before the draft is approved, and not something the builder can do from the repo:
1. `TGL_AEO_ENDPOINT` must be set on the staging WordPress to the public URL of `/aeo/lead` on the tgl-ops service. Empty means the form shows "temporarily unavailable" and never success.
2. `AEO_ALLOWED_ORIGINS` on the service must include the staging origin, or the browser POST gets 403.
3. GHL variables (`GHL_API_KEY`, `GHL_LOCATION_ID`, `GHL_AEO_PIPELINE_ID`, `GHL_AEO_STAGE_NEW_ID`) must be set on the service, or it answers 503.
4. One live submission from the staging page with a lead named `TEST-HOME` should be made and the GHL opportunity checked, then the test contact deleted. A fake-GHL test does not prove the live credentials.
